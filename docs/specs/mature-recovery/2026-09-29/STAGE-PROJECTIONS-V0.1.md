# ShareCLI stage projections — mature-contract projections v0.1

Status: **PROVISIONAL / no disposable mini-products**  
Date: 2026-09-30.

Stages project the mature ontology; they do not redefine it.

## CVP — trustworthy local coordination spine

Must close:
- SC-J01 trustworthy local observation;
- SC-J02 owned lifecycle for one supported platform;
- SC-J05 local session recovery vertical slice.

Breadth may be stubbed:
- one Principal/Project;
- one platform;
- one session/surface provider;
- no durable command reuse;
- no distributed/remote coordination;
- FUSE off unless needed by the selected fixture.

Mature identities already used:
PolicyDecision, ProcessGeneration, OwnershipClaim, RecoverySubject/Operation, Observation/Evidence.

## MVP — admission + bounded mediated optimization

Adds:
- SC-J03 admission for selected workload families;
- one native AdmissionProvider integration where applicable;
- ProductLeaseProvider for one non-native family;
- SC-J04 in-flight sharing for one explicit equivalence adapter;
- capability-truth CLI/API.

Durable replay remains disabled unless one adapter separately proves it.

## Beta — optional adapters and operator breadth

Adds:
- durable reuse for adapters that independently qualify;
- explicit optional/required FilesystemSession;
- resource policy/operator UI;
- broader session/surface providers;
- lifecycle/update/uninstall proof;
- second supported platform.

## GA

Requires:
- supported journey/platform matrix;
- security/authorization review;
- schema/update compatibility;
- exact evidence/trace validator;
- accessibility/operator-quality gates;
- no unresolved critical false-green path;
- documented unsupported capability states.

## Mature

Adds breadth only where thesis survives:
- more equivalence/admission/native-tool adapters;
- additional platforms/providers;
- richer local coordination;
- optional remote/distributed expansion only after separate authority/architecture gate.

## Transition debt rules

- CVP PID-only identity is forbidden; use mature ProcessGeneration abstraction even if only one provider exists.
- CVP session persistence cannot use a disposable schema incompatible with RecoverySubject/Operation.
- MVP in-flight sharing cannot be implemented by pretending the old durable cache is in-flight-only.
- stage-specific stubs must identify replacement/growth disposition.


## Thesis correction overlay — 2026-09-30

The original projection underweighted the core optimization thesis.

### Revised CVP requirement
In addition to observation/owned lifecycle/session recovery, CVP MUST close one measurable scheduling/resource-packing journey:
- >=2 competing WorkItems;
- explicit ResourceEnvelope;
- explicit SchedulingPolicy;
- queue/admission/placement decision;
- no resource-envelope violation;
- measured comparison against naive concurrent execution.

This may use a deterministic rule-based scheduler. Learned/predictive optimization is not required.

### Revised MVP
MVP must exercise multiple optimization strategies under one common scheduler/control model, such as:
- queue/admission;
- packing;
- coalescing/in-flight sharing;
- pressure-driven throttle/replan.

### Mature
Mature ShareCLI is judged partly by its ability to improve useful work under constrained resources/time horizons versus realistic native/status-quo scheduling. Process/session features support this thesis; they do not replace it.
